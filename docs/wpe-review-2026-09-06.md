## Findings, in priority order

1. **P1 — WPE does not enforce `sandbox: true` at the native bridge boundary.** [Bridge registration](/home/pi/src/electrobun/package/src/native/linux/wpe/wpe_backend.cpp:1221) unconditionally exposes `bunBridge` and `internalBridge`; [view assignment](/home/pi/src/electrobun/package/src/native/linux/wpe/wpe_backend.cpp:919) binds their handlers without consulting `spec.sandboxed`. Core passes both privileged trampolines even for sandboxed views. A page can call `window.webkit.messageHandlers.internalBridge.postMessage(...)` directly, bypassing the restricted preload. That reaches privileged internal messages, including [JavaScript execution in another view](/home/pi/src/electrobun/package/src/core/main.zig:2323). GTK explicitly suppresses these bridges for sandboxed views. WPE also [ignores allowedProtocols](/home/pi/src/electrobun/package/src/native/linux/nativeWrapper_wpe.cpp:387). Enforce sandbox and protocol policy in native code on every pool assignment and dispatch, retaining only the event bridge for sandboxed content. Restrict the decoration bridge to the framework-owned chrome view. Hello's About window currently requests this ineffective sandbox.

2. **P1 — New Core arguments break the Rust, Zig, Go, and Odin webview ABI.** [configureWebviewRuntime](/home/pi/src/electrobun/package/src/core/main.zig:1483) gains an embedded flag, and [createWebview](/home/pi/src/electrobun/package/src/core/main.zig:2971) gains a trailing trust pointer. Only the TypeScript binding was updated. For example, [Rust's signatures](/home/pi/src/electrobun/package/src/sdks/rust/electrobun.rs:654) and [Zig's call](/home/pi/src/electrobun/package/src/sdks/zig/electrobun.zig:1476) still use the old arguments; Go and Odin do too. WPE can pass an indeterminate trust pointer to `strcmp`, causing undefined behavior or a crash. Preserve the existing ABI with separate capability setters/versioned entrypoints, or update every SDK and explicitly version the ABI. The passing native-symbol tests check names, not argument signatures, and omit the WPE wrapper.

3. **P1 — WPE dispatches only parts of view operations to the WebKit thread.** [createWebview](/home/pi/src/electrobun/package/src/native/linux/wpe/wpe_backend.cpp:849) mutates `freePool_`, `activeViews_`, callbacks, and view size outside `dispatchSyncMain`; only lazy construction and initial navigation are dispatched. [Load/back/reload/remove/resize exports](/home/pi/src/electrobun/package/src/native/linux/nativeWrapper_wpe.cpp:474) also call into WebKit/pool state directly. Core calls these on the runtime's calling thread, while input, frame export, and composition iterate the same state on GLib. This creates both WebKit thread-affinity violations and unsynchronized vector/state access. Marshal each whole operation onto one designated WebKit thread. Perform pool assignment, preload configuration, sizing, and URL loading as one transaction; do not rely on scattered dispatches or merely owning a GLib context. Source-confirmed; no race stress was run against the live kiosk.

4. **P1 — Unexpected Hermes disconnection abandons active media resources.** [App's onDisconnected](/home/pi/src/hermes-desk/src/mainview/App.tsx:192) sets `connectionRef.current = null` and clears UI state without calling `disconnect()`. [Realtime's connection-state callback](/home/pi/src/hermes-desk/src/mainview/realtime.ts:60) invokes this for even a transient `disconnected` state; the microphone tracks, peer, and silent AudioContext remain alive. Conference similarly loses its room reference from the app when the signaling socket closes, even if the media room remains connected. An offline mock reproduced a dropped app reference with microphone, peer, and AudioContext all still open. Use one idempotent teardown path, retain the connection until cleanup completes, and guard callbacks with a connection generation so an old session cannot clear a newer one. Give transient ICE disconnection a bounded recovery interval. Any automatic reconnect should honor the intended microphone-consent policy.

5. **P1 — Hermes's clean kiosk build can combine a vanilla renderer SDK with the WPE runtime.** [build:kiosk](/home/pi/src/hermes-desk/package.json:16) runs Vite **before** selecting/preparing the WPE devkit, while [Vite aliases](/home/pi/src/hermes-desk/vite.config.ts:4) resolve `electrobun/view` through the existing `.hutch/devkit`. After a fresh install or switching from vanilla, the first renderer build can embed the vanilla receiver. WPE Core now sends encrypted binary frames, and vanilla's receiver ignores Blob frames. Requests such as `getSettings` can then time out. Today's cached devkit is already WPE, masking this path. Prepare the selected devkit first, then build the renderer and app with that same selection. Record/check a runtime-and-renderer compatibility identifier, or negotiate binary transport support before sending binary. This fresh-install failure path is established from source; no package installation or app rebuild was performed.

6. **P2 — A new import cycle breaks the BrowserView entrypoint.** The added [native.ts import of BrowserWindow](/home/pi/src/electrobun/package/src/sdks/main/proc/native.ts:10) creates `BrowserView → native → BrowserWindow → native`; [BrowserWindow's module initialization](/home/pi/src/electrobun/package/src/sdks/main/core/BrowserWindow.ts:9) dereferences `ffi` before initialization. `bun test ./src/sdks/main/core/BrowserViewHostMessageQueue.test.ts` fails with that ReferenceError on WPE and passes on a temporary checkout of current main. Move shared embedded-state/window-registry functionality to a dependency without initialization side effects, or resolve the window dependency only when handling a chrome action. This also needs fixing before recommending narrower main-process imports to reduce startup work. Both apps' bundled renderer builds pass; that does not cover this source-level SDK entrypoint.

7. **P2 — Binary RPC bypasses Linux's FIFO dispatch guarantee.** [The binary receive branch](/home/pi/src/electrobun/package/src/browser/index.ts:101) awaits decryption independently for each frame and immediately invokes the handler. The existing text branch uses `queueLinuxHostSocketDispatch` to preserve arrival order despite asynchronous WebCrypto completion. An offline harness resolving the second decrypt first delivered binary messages as `[2,1]`; the text control delivered `[1,2]`. Feed both decoded formats through the same ordering queue. Keep decryption concurrent and serialize delivery only.

8. **P2 — A compositor failure can permanently stop frame production.** [composeAndPresent](/home/pi/src/electrobun/package/src/native/linux/wpe/wpe_backend.cpp:1721) returns immediately on a failed EGL compose/readback. The only active-view `frame_complete` acknowledgments are later, after presentation. A failed frame therefore leaves WPE waiting for completion, with no retry or fallback scheduled; a single-view kiosk can stay frozen indefinitely. Model frame ownership and completion explicitly. On failure, safely finish/drop the affected frame and retry with a bound, recover the backend, or exit so the service can restart. Buffer release must remain synchronized with GPU use. Also propagate `DrmDisplay::present()` failure instead of counting an unsuccessful flip as a rendered frame.

9. **P2 — Window-close vetoes are bypassed by WPE's titlebar button.** [The chrome Close action](/home/pi/src/electrobun/package/src/native/linux/nativeWrapper_wpe.cpp:125) calls `closeWpeWindow` directly. [requestWindowClose](/home/pi/src/electrobun/package/src/native/linux/nativeWrapper_wpe.cpp:268) already routes through `shouldCloseCallback`, but the button does not use it. User close handlers cannot veto a titlebar close, potentially skipping confirmation or orderly session cleanup. Route user-initiated closes through the request path, retaining direct close only for an approved/programmatic close.

10. **P2 — Embedded visibility, passthrough, and alpha do not match the exposed API.** [WPE's window visibility exports](/home/pi/src/electrobun/package/src/native/linux/nativeWrapper_wpe.cpp:259) are no-ops; view hidden/transparent setters inherit no-op implementations. [Input hit testing](/home/pi/src/electrobun/package/src/native/linux/wpe/wpe_backend.cpp:1929) ignores `isMousePassthroughEnabled`. [EGL rendering](/home/pi/src/electrobun/package/src/native/linux/wpe/egl_readback.cpp:376) disables blending, and SHM composition uses unconditional copies. An overlay intended to be hidden, transparent, or click-through remains visible/opaque or captures input. Make visible/input/opaque state part of the layer model, apply it consistently to rendering and hit testing, and use premultiplied-alpha blending for transparent layers. Explicit capability errors would be preferable to silently accepting unsupported operations.

11. **P2 — Conference-only unattended startup is incorrectly gated on the Realtime key.** [The autoconnect effect](/home/pi/src/hermes-desk/src/mainview/App.tsx:123) returns unless `settings.realtimeApiKey` exists, even when Conference is selected and its key is valid. A conference-only kiosk therefore remains at Start after a boot or watchdog restart. Check the selected transport's required settings and trigger the connection operation directly after settings load, instead of querying/clicking the DOM button.

12. **P2 — Camera failures can appear healthy, and MJPEG preview does not reconnect.** [CameraState.fail](/home/pi/src/hermes-desk/scripts/hermes-camera-sidecar.py:60) retains the previous JPEG; both `/state` and `/health` report readiness using only whether a frame exists. A simulated capture failure reproduced `ready: true` with an error and retained stale frame. `/frame.jpg` likewise keeps returning 200. Separately, [App's image error handler](/home/pi/src/hermes-desk/src/mainview/App.tsx:274) only changes a label; successful health polls never change `img.src`. If the sidecar starts late or restarts, the preview may never reconnect and the UI can report live over a stale/failed image. Use a monotonic frame-age threshold plus capture error for health, enforce freshness for screenshot tools, and reconnect the MJPEG image with bounded backoff and a new request URL. Preserve the sidecar architecture; do not return to WPE camera `<video>`.

13. **P2 — The embedded installer does not atomically replace its `current` link.** [installEmbeddedKiosk](/home/pi/src/electrobun/package/src/extractor/main.zig:2442) deletes `current` before creating its replacement. Failure or interruption between operations leaves the configured launcher path absent, contrary to the adjacent atomic-selection comment. Create a temporary sibling link, then rename it over `current`, checking errors and retaining the previous target for recovery. This affects versioned installer deployments, not Hermes's currently running development bundle. The installer also overwrites the account-wide `portals.conf` and restarts the portal service even with `--no-kiosk`; scope that configuration to the kiosk environment or preserve existing user configuration.

## Startup and rendering optimization priorities

The changes below can reuse the existing WebRTC-enabled WPE WebKit library. Some require rebuilding Electrobun's small native wrapper, SDK bundles, or launcher; none inherently requires rebuilding WebKit itself.

| Priority | Change | Why it is worth measuring | Build scope |
| --- | --- | --- | --- |
| 1 | Eliminate synchronous full-frame CPU readback from normal presentation | `composeToScanout` still calls `glReadPixels` into a DRM dumb buffer. At 1920×480×4×60, that is 221 MB/s of pixel payload, before extra copies, plus a GPU completion wait on the input/bridge loop. Compose into scanout-capable GBM buffers and page-flip with correct image/buffer lifetime and fences. | Electrobun wrapper/compositor |
| 2 | Make idle Hermes genuinely idle at the renderer level | The ring animation runs continuously even when disconnected/muted, causing repeated exports and full-frame composition. Pause or reduce animation in idle/occluded states; keep the desired animated speaking/listening states. Expose a sidecar preview-FPS policy independent of capture/detector FPS. | Renderer and sidecar |
| 3 | Select one devkit before every renderer/app build | Prevents the concrete binary-protocol mismatch above and makes benchmark comparisons meaningful. Keep a reproducible vanilla/WPE build matrix in Hello Embedded. | Build scripts/config |
| 4 | Reduce main-process startup imports after fixing the cycle | Both apps import the broad `electrobun/main` entrypoint. Measure the actual current main bundle and module initialization, then use the narrow BrowserWindow/BrowserView/menu entries where supported. Do not assume historical 5–9 MB measurements in linux-wpe.md describe today's v2 bundles. | SDK/app JS |
| 5 | Bound and gate Hello's Vite probe | [getMainViewUrl](/home/pi/src/hello-embedded/src/bun/index.ts:87) always HEAD-probes localhost with no abort deadline and accepts any HTTP response. A hanging local server delays first-window creation, including release builds. Probe only in development, require an OK response, add a short deadline, and make the host configurable for cross-machine HMR. | App JS |
| 6 | Make launcher prefetch match the selected runtime | [readaheadStartupFiles](/home/pi/src/electrobun/package/src/launcher/main.zig:141) advises `bun` but both apps use `cottontail`. It also advises the entire ASAR, including assets unrelated to the first screen, and always runs a double-fork/dlopen warmer. Resolve the runtime first, advise the needed files/ranges, and compare cold/warm starts with preheat enabled and disabled. | Launcher |
| 7 | Remove obsolete bridge copies and delayed frees | [forwardBridgeMessage](/home/pi/src/electrobun/package/src/native/linux/wpe/wpe_backend.cpp:1428) retains two payload buffers and a GLib timeout for each bridge message. Current [Core trampolines](/home/pi/src/electrobun/package/src/core/main.zig:483) already copy/own callback payloads. Align WPE with the current GTK ownership contract and free the temporary JSC string immediately after the synchronous trampoline returns. | Wrapper |
| 8 | Overlap Conference's vendor loading with authentication | LiveKit's 556 kB renderer chunk is correctly lazy-loaded, but import starts only after both signaling round trips. Start one import promise when Conference connection begins and await it before constructing the room. Also abort pending HTTP/signaling operations during disconnect and apply deadlines to Realtime call creation and camera-tool fetches. | App JS |

GPU presentation is the largest architectural opportunity, but it needs device validation. The Pi separates V3D rendering from VC4 display; allocation/import compatibility must be verified rather than assuming a render-node buffer is directly usable for KMS. [Mesa's V3D documentation](https://docs.mesa3d.org/drivers/v3d.html) describes this split and its buffer-management helpers. An asynchronous PBO path could reduce blocking if supported, but it can add queued-frame latency; it should be evaluated as a fallback, not assumed to improve touch-to-display latency.

Start with demand reduction and lifecycle fixes, then address presentation. Reusing a small layer vector, avoiding the per-touch `std::vector` allocation with a fixed 16-element array, caching constant policy objects, and gating SHM's remaining periodic frame logs are smaller follow-ups. They should come after measuring readback and continuous repaint costs.

## Cyclomatic complexity

Measured with Lizard 1.24.0 on the current C++ source. CCN counts branches and boolean decisions; it is a review aid, not a performance metric. Targets below are design suggestions, not claims that splitting functions alone improves execution speed.

| Function | CCN | Suggested restructuring |
| --- | ---: | --- |
| `WpeBackend::createWebview` | 38 | One main-thread operation calling pool acquisition, normalized geometry, policy/preload binding, and grouped z-order insertion helpers. Use an explicit logical-window record rather than parallel maps and repeated vector scans. |
| `WpeBackend::onInputEvent` | 32 | Separate coordinate transforms, target selection, and touch lifecycle. Reuse one transform implementation for rendering/input; use fixed touchpoint storage. Handle cancellation/removal explicitly. |
| `EglReadback::Impl::initialize` | 30 | RAII wrappers for render-node/GBM/EGL/GL resources and separate device/context, program, and output-target setup. This also simplifies failure cleanup. |
| `WpeBackend::composeAndPresent` | 27 | A shared frame state machine plus EGL and SHM composition strategies. Centralize completion, retry, and release semantics instead of returning before required cleanup. |
| `EglReadback::Impl::render` | 22 | Extract rotation/viewport calculation and output transfer; choose the output strategy once at initialization. |
| `WpeBackend::setWindowMaximized` | 20 | Store primary/chrome/restore geometry together per window and apply a single desired-layout transition. |
| `handleViewsURIScheme` | 18 | Separate validated URL/path resolution, ASAR/filesystem access, and response completion; move asset I/O off the event loop if profiling shows it delays input. |

For Hermes, the useful reduction is an explicit connection state model shared by both transports, a separate camera-preview hook, and a reducer for session events. `busy`, `connected`, `muted`, refs, callbacks, and status-string matching currently encode overlapping lifecycle states, contributing to the confirmed teardown bug. Avoid spending effort shortening harmless JSX conditionals while that ownership remains ambiguous.

Pooling also needs a complete reset contract: [recyclePooledView](/home/pi/src/electrobun/package/src/native/linux/wpe/wpe_backend.cpp:636) does not clear navigation rules, passthrough state, or backend touch capture referring to that slot. Clear/cancel those before reuse, and test close/reopen while a touch or frame is pending. The finite pool and trusted-process reuse are reasonable memory optimizations to preserve.

## Hello Embedded and camera compatibility follow-ups

- Hello's checked-in [Hutch config](/home/pi/src/hello-embedded/hutch.config.ts:1) pins Electrobun 2.0.1 and older Hutch/Cottontail versions; its build script does not encode the sibling WPE-devkit selection. The existing installed Electrobun reports 2.0.2-beta.14, so a successful local build does not establish a fresh-checkout vanilla/WPE contract. Document two explicit selections and run both through prepare → renderer build → app packaging without changing application source.
- Its normal typecheck currently fails at `ignoreDeprecations: "6.0"`: installed TypeScript is 5.9.3 even though package.json pins 6.0.3. A diagnostic run with `--ignoreDeprecations 5.0` then failed with TS7016 for `three`; `@types/three` is absent from Hello's declared dependencies. Resolve the install/lock/toolchain mismatch and missing type declarations. Dependencies were not reinstalled during this review.
- Hello's external-site button navigates the privileged main view to Google. Since WPE retains the view's trust class and injects preload across navigation, external pages retain its capabilities, including the automatic media-permission policy. Open external content in an explicitly sandboxed/untrusted view after fixing native sandbox enforcement, or use a navigation allowlist and an external-browser action on supported targets.
- The perf page measures rAF callbacks and one RPC RTT per interval. It is useful as a load generator, but rAF is not a page-flip timestamp. Normalize counts by actual elapsed time, prevent overlapping timed-out pings, and capture percentiles for RPC, export-to-present, and input-to-present separately.
- Camera screenshots permit 40 KiB JPEGs, becoming about 53 KiB before the JSON envelope. The legacy LiveKit RPC path has a 15 KiB payload limit, also documented in [LiveKit RPC guidance](https://docs.livekit.io/transport/data/rpc/). Installed SDK 2.22.0 explicitly supports larger responses for peers with the newer data-stream RPC protocol, so this is a **peer compatibility constraint**, not a universal 15 KiB limit. Negotiate/verify the peer protocol or use a bounded image-transfer path. `conference.tools` currently publishes results as ordinary data packets, for which [LiveKit recommends the 15 KiB user-payload limit](https://docs.livekit.io/transport/data/packets/) for compatibility.
- Desktop camera preview uses browser capture, but `executeCameraTool` always fetches the Linux sidecar. A normal macOS development launch without that sidecar cannot supply the advertised screenshot/state tools. Introduce a camera-provider interface with explicit desktop and sidecar implementations; retain the bounded sidecar provider on Linux.
- The README still describes two-second JPEG polling in one section, while the deployed source uses a continuous MJPEG image with a default sidecar publication rate of 15 fps. Update the description so future work does not mistake the health-poll interval for preview FPS.
